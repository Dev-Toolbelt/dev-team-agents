# ADR-0007: Global core and data store replacing per-project vendored install

**Date:** 2026-09-27
**Status:** Accepted
**Deciders:** dev-team-agents maintainers

## Context

Until v2, `install.sh` copied the whole canonical tree into every target project at
`.dev-team-agents/` — 325 files, ~2.3 MB — and `install.sh` (Step 10) added only
`user-data/`, `credentials.local.json`, `.worktree-session` and `.learn-last-run` to the
project's `.gitignore`. Everything else was therefore **committed into each project's git
history**. A user with 10 projects carried 10 copies and ran 10 updates, and every update
produced a framework-sized diff in a product repository.

Two properties of that layout were load-bearing and must be accounted for, not discarded by
accident:

1. The Claude links are **relative** (`install.sh:592` — `ln -s ../../.dev-team-agents/agents`),
   so the committed symlink blobs resolve on a teammate's fresh clone. A store outside the
   repository can only be reached by an **absolute** path, which differs per machine and per
   user name.
2. On Windows without native symlinks, git materialises links as ~62-byte text files
   (`README.md:263`, `scripts/fix-symlinks.sh`). That failure mode is already documented; a
   global store makes it systemic rather than incidental, because every project link points
   outside the repository.

## Decision

Split the installation into two stores with different lifetimes, and reduce the project to a
thin, reconstructible bind.

**Core** — the canonical tree, immutable per version, disposable:

```
macOS    ~/Library/Application Support/dev-team-agents/core/versions/<version>/
         ~/Library/Caches/dev-team-agents/render/
Windows  %LOCALAPPDATA%\dev-team-agents\core\versions\<version>\  ,  \cache\
Linux    $XDG_DATA_HOME/dev-team-agents/core/versions/<version>/   (not a release target yet)
```

**Data** — everything the user would be upset to lose, surviving uninstall:

```
macOS    ~/Library/Application Support/dev-team-agents/data/
Windows  %APPDATA%\dev-team-agents\data\      (covered by profile backup)

data/
├── registry.json            bound projects: id, path, providers, mode, pin, timestamps
├── preferences.json         global user preferences
├── credentials/             references only, never a secret value (see ADR-0010)
└── projects/<project_id>/   per-project memory, preferences, audit log
```

`$DEVTEAM_HOME`, when set, overrides the OS convention and places `core/`, `cache/` and
`data/` beneath it. This is the single hook the test suite uses, so tests never touch a real
user directory.

**The `current` pointer is a file, not a symlink.** `core/current` contains a version string.
A symlink here would reintroduce, at the centre of the design, the exact Windows failure mode
described above.

**A project holds only:**

```
<project>/.dev-team-agents/project.json   committed: schema, project_id, context_paths
<project>/.dev-team-agents/core           pointer to the resolved core version
<project>/.dev-team-agents/user-data/     project memory (v2 location, moved in a later step)
<project>/.claude/settings.json           hook dispatchers, merged (project-owned, committed)
<project>/.claude/… .opencode/… .codex/…  bind artifacts — ignored, regenerated by sync
```

**The `core` pointer is load-bearing, not a convenience.** 116 shipped references reach the
framework through a project-relative path — 103 to `.dev-team-agents/scripts/…` across six
commands and fourteen skills, 13 to `.dev-team-agents/templates/…`, including this repository's
own mandated `bash .dev-team-agents/scripts/new-adr.sh`. An earlier cut of this design left
`.dev-team-agents/` holding `project.json` alone, and every one of those references broke; the
bash provider installers then quietly restored a working path by copying 2.3 MB of framework
back into the project, which is the exact outcome this ADR exists to prevent. One pointer
(symlink in `link` mode, copy in `copy` mode, recorded in the manifest) satisfies all of them.
Rewriting 116 references to resolve the store at runtime was the alternative; it is a larger
change, it would have to be repeated for every future reference, and it buys nothing.

**Hook dispatchers are part of the bind.** v2's `install.sh` registered four entries in
`.claude/settings.json` (`SessionStart`, `Stop`, `PreCompact`, `PreToolUse`). They are what makes
the session banner, the session-summary enforcement, the orphan-skill scan, the agent lint and
the ADR-gap check run at all — `CLAUDE.md` § Agent Memory System calls that dispatcher the
reason three of its rules are "enforced automatically after installation". A bind that produces
agents, commands and skills but no hooks is not an installation of this framework. The bind
merges those four entries into the project's own `settings.json`, rewrites a stale v2 path in
place rather than adding a second entry, and removes only its own entries on `unbind`.

**`registry.json` and the per-project manifests are machine-local.** They hold absolute paths
from one machine, so restoring a roaming profile onto a new machine produces a registry that
names directories which do not exist there. Memory is portable; bind state is not, and they
share the `data/` tree. `devteam doctor` reconciles a single moved project, and `devteam sync`
rebuilds artifacts — a wholesale restore is expected to need both, not to work untouched. This
is stated rather than fixed because splitting the tree per host is a later decision; silence
here would read as a promise the store does not keep.

> **Amended by [ADR-0013](0013-portable-and-machine-local-split-of-the-data-store.md).** The two
> kinds of record no longer share the `data/` tree: machine-local records live under
> `data/machines/<machine-id>/`, keyed by an id that is re-issued when the store is opened on a host
> other than the one that recorded it, and `devteam export` is portable by default — it excludes
> `machine-id`, `machines/`, `locks/`, `quarantine/` and any machine-local record at every path
> depth, while `--all` takes everything but `locks/`. A portable archive plus each project's
> committed `project.json` is enough to rebuild a bind on another machine, and an import withholds
> the consent keys so the receiving machine is asked again. `devteam doctor` still reconciles a
> single moved project and `devteam sync` still rebuilds artifacts; what changed is that a
> wholesale restore is no longer expected to arrive holding another machine's paths.
>
> **The tree above is left as ADR-0007 decided it** — `docs/development/adrs/` is the decisional
> layer, and a reader has to be able to see what was decided here rather than a later shape
> back-written into it. For the current tree, read ADR-0013.

Bind artifacts are **gitignored**, written between managed markers in `.gitignore`, because an
absolute path to one developer's `$HOME` cannot be committed. `devteam bind` recreates them,
and `devteam sync` refreshes them after an update or a config change.

**Three bind modes**, recorded in `registry.json` so the mode is never implicit:

| Mode | Artifacts | Default where |
|------|-----------|---------------|
| `link` | symlinks into `core/versions/<v>` | macOS, Linux |
| `copy` | copies of the same trees, refreshed by `sync` | Windows without native symlink support |
| `vendored` | full tree inside the project, v2 behaviour | opt-in: CI, containers, air-gapped |

**Versions are addressable and pinnable.** A project with no pin follows `core/current`; a
pinned project stays on its version until released. This is what keeps "update once" from
meaning "move ten projects mid-sprint", and it makes rollback per project rather than global.

## Consequences

### Positive
- One install, one update. `devteam update` writes a new version and `devteam sync --all`
  re-points every bound project that is not pinned.
- Product repositories stop carrying framework files; `git log` stops showing framework diffs.
- Per-project pinning and rollback become possible for the first time.
- The render cache is shared per (version, provider) instead of recomputed per project.
- Uninstalling the app no longer destroys memory: `data/` is a separate tree, and only
  `devteam uninstall --purge` removes it, after explicit confirmation.

### Negative
- A fresh clone no longer carries the harness. Each developer must install the store and run
  `devteam bind` once. `vendored` mode exists for the cases where that is not acceptable.
- Windows becomes a first-class platform with the weakest mechanism (`copy`), which needs an
  explicit refresh step that `link` does not.
- Two stores mean two failure surfaces; `devteam doctor` has to reason about both.

### Neutral
- `$DEVTEAM_HOME` keeps a single-directory layout available for users who prefer it, and is
  the test seam.

## Alternatives Considered

| Alternative | Why rejected |
|-------------|-------------|
| Install agents/commands/skills at the user level (`~/.claude/…`) and keep nothing in the project | The harness would load in **every** project on the machine, including ones never onboarded. Kills per-project opt-in and per-project pinning, and would surface `/devteam:*` in unrelated repositories. |
| Keep vendoring as the default and offer the store as an option | Preserves clone-and-run, but leaves the duplication that motivated the change. Retained as the `vendored` **mode**, not as the default. |
| One version in the store, shared by all projects | Simpler (no pin, no GC), but a regression reaches all ten projects at once and rollback is global. Rejected on blast radius. |
| `core/current` as a symlink | Reintroduces the Windows materialisation failure at the most load-bearing path in the design. A text file has no such failure mode. |

> **Amendment — `bind` refuses a v2 vendored install; `migrate` is the only way in.** `bind` treated
> the relative links a v2 `install.sh` committed as its own and replaced them, but left the vendored
> tree under `.dev-team-agents/` in place and tracked — and once `project.json` existed, `doctor`'s v2
> check no longer ran, so the project reported `status: ok` with 324 framework files and ~150 links
> into one machine's store still in git. Found on a real project, not in review. Three changes: the
> `bind` **command** exits 4 on a v2 install and names `devteam migrate` (the check is in `cmd_bind`,
> not `bind()`, because `sync` and `migrate` call `bind()` and must keep working on a project already
> in that state; `--mode vendored` is exempt, since that path quarantines the tree itself); `doctor`
> reports a leftover v2 tree whether or not the project is bound; and both `doctor` and `migrate`
> report machine-local bind artifacts that git still tracks, with the exact `git rm -r --cached`.
> Neither runs it: the index belongs to the user. Machine-local is an allowlist of manifest kinds
> (`bind.MACHINE_LOCAL_KINDS`), and `settings` is left out on purpose — `.claude/settings.json` is the
> project's own file, which a teammate needs committed to get the hooks.
