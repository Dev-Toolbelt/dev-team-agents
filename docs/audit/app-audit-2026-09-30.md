## Audit Report: app

### Scope
The Electron desktop client in `app/`: main process (`src/main/`), the CLI spawn layer (`src/cli/`), the preload, `src/shared/`, the React renderer (`src/renderer/`), tests (`app/test/`), and build and CI (`electron-builder.yml`, the vite configs, `.github/scripts/ci/05-app.sh`). The app is a pure CLI client (ADR-0011, 0014, 0015, 0016, 0017). It spawns the python `devteam` CLI with `--json` and never touches the store directly. The architecture is layered: main ↔ preload bridge ↔ renderer, with a CLI layer that imports nothing from Electron.

Baseline at audit time: typecheck, lint and 399 tests all passed, with 1 skipped. No TODO or FIXME markers.

The fundamentals are already sound, and the fixes must not regress them:
- context isolation, sandbox and a strict CSP;
- `shell:false` spawns and an argv allow-list (`COMMAND_SHAPES`);
- bind paths that come only from the native picker;
- project ids resolved against the registry;
- consent keys confirmed in a native dialog;
- an allow-listed child environment.

### Critical Issues
| # | Severity | Layer | Description | Suggested Fix |
|---|----------|-------|-------------|---------------|
| 1 | high | FE | `ProjectSettings` is rendered without a `key`, and `useOperation` keeps the previous result when deps change. Unsaved drafts from project A leak into project B, where Save writes them to B. | Add `key={project_id}`. `useOperation` resets to loading when deps change, and keeps the stale result only on a same-deps reload. |
| 2 | med-high | BE | Gated (write) commands run with the 20 s read timeout. A slow `bind`, `sync --all`, `upgrade --apply` or `skills install` is killed mid-write and leaves a stale store lock for about 5 minutes. | Give gated commands a longer timeout in `run()`. |
| 3 | med | BE | After a timeout kill, `invokeDevteam` waits only for `close`. A grandchild process holding the pipes hangs the IPC call forever. | Settle on `exit`, then after a short grace period destroy the pipes. |
| 4 | med | FE | `useAction.run` has no catch, and neither does Doctor's `useLoaded`. A rejected IPC call leaves buttons or forms stuck in "pending" forever. | Convert rejections into an `unavailable` result, as `useOperation` does. |
| 5 | med | FE | There is no error boundary, and `App.load` has no try/finally. A render throw blanks the window, and a rejected startup call leaves the app stuck on "Looking for a devteam CLI…". | Add a root error boundary and per-screen boundaries. Use try/catch/finally in `load()`. |
| 6 | med | FE | The Unbind, Upgrade and Bind dialogs reload the project list only from "Done". Closing with Esc or clicking outside after a successful write leaves the list stale. | Reload as soon as the write succeeds, as Skills already does. |
| 7 | med | FE | When the project list fails to load, there is no retry control. | Render a "Try again" button next to the problem. |
| 8 | med-low | BE | `writeSettings` rewrites a corrupt or unreadable `settings.json`, losing `cliPath`. Concurrent writes are not serialized, so updates get lost. | Refuse to write over a file that has a problem. Serialize writes. |
| 9 | low-med | BE | The `second-instance` handler is registered before ready and can create a `BrowserWindow` before the app is ready. | Only `showWindow()` when `app.isReady()`. |
| 10 | low | BE | `ensureResolution` caches the result rather than the in-flight promise, so concurrent calls each run the probe walk, and a reset can be overwritten. | Cache the promise and clear it on reset. |
| 11 | low | FE | `UnbindDialog` never resets, so reopening it shows a stale report or error. Closing while a write is pending drops the result. `projectNames()` has no catch. | Reset on close. Block close while pending. Add `.catch`. |

### Security Findings
- **[MED] S1: `file:` navigation plus no IPC sender check.** Dropping an `.html` file on the window navigates to it (`file:` is allowed), and the preload hands that page the full `window.devteam` API. Fix: allow navigation only to the exact renderer URL, deny `will-frame-navigate` too, and reject IPC whose `senderFrame.url` is not the app's own renderer.
- **[MED] S2: `pin` version is unvalidated end to end.** The app accepts any string (`ipc.ts` `validateBindRequest`, `setPin`), and the CLI joins it onto `versions_dir()` (`versions.py`, `paths.py`), so an absolute path or `..` points the project at arbitrary content, including hooks. Chained with S1, this is code execution in the next agent session. Fix: validate the version shape in the app, and in the CLI require the resolved target to stay inside `versions_dir()`.
- **[LOW] S3: no Electron fuses.** `RunAsNode`, `NODE_OPTIONS` and `--inspect` are enabled in the packaged build. Fix: an `electronFuses` block in `electron-builder.yml`.
- **[LOW] S4: `DEVTEAM_APP_DEV_SERVER` is honoured in packaged builds, and the origin check is a prefix match.** `http://localhost:5173.evil.tld` passes. Fix: ignore the variable when `app.isPackaged`, and compare parsed origins.
- **[INFO] S5: DevTools are reachable in the packaged build.** Fix: `devTools: !app.isPackaged`.

### Infrastructure Findings
- **[HIGH] D1:** CI never runs `npm run build`, so a broken tsc or vite emit ships green. Fix: add the build plus a check that its outputs exist to `05-app.sh`.
- **[HIGH] D2:** the Windows NSIS target has no script and is never exercised. Fix: add `dist:win`. Running per-OS `electron-builder --dir` on tags is recommended as a follow-up, since it needs a job with scripts enabled.
- **[MED] D3:** `real-cli.test.ts` skips silently when python3 or the CLI is missing, so the CLI contract can go untested in CI while CI stays green. Fix: fail when the CLI is unavailable under `CI=true`.
- **[MED] D7:** a packaged build has no log file and no crash handlers, so a CLI spawn failure or a notification-stream crash loop leaves nothing to diagnose. Fix: a small rotating log under `app.getPath('logs')`, plus `uncaughtException`, `unhandledRejection` and `render-process-gone` handlers.
- Out of scope (need credentials or a product decision): signing and notarisation, Node 20 test runtime versus Electron's bundled Node 22, auto-update, and a scripts-enabled per-OS packaging job.

### Improvement Plan (ordered by value)
1. S1 + S2: navigation allow-list, IPC sender check, and pin validation in the app and the CLI. This closes the only code-execution chain. Effort M.
2. #1: `ProjectSettings` key plus `useOperation` deps reset. Prevents a wrong-project write. Effort S.
3. #2 + #3: write timeout and a pipe-holding grandchild. Prevents half-applied writes, lock storms and a hung UI. Effort S.
4. #4, #5, #7: rejection handling, error boundaries and list retry. The UI can no longer get permanently stuck. Effort S–M.
5. #6, #11: dialog list refresh and reset. Stale list after writes. Effort S.
6. #8, #9, #10: settings integrity, second-instance guard and resolution de-duplication. Effort S.
7. S3, S4, S5: fuses, dev-server gating and DevTools. Hardening before signing lands. Effort S.
8. D1, D2, D3: CI build step, `dist:win` and loud real-CLI skip. Removes CI false-greens. Effort S.
9. D7: packaged-build log file and crash handlers. Makes failures diagnosable. Effort S–M.

### Recommended Next Steps
- Implement items 1–9 in four parallel tracks: main/CLI layer, renderer, CI/packaging, and the python CLI pin guard. Then run two review rounds.
- Before the first signed release, add a scripts-enabled, per-OS `electron-builder --dir` job on tags (needs its own `npm ci`).

### Outcome
All items 1–9 are implemented on branch `audit/app`, followed by two review rounds.
- **Round 1:** backend, frontend and a security re-check. It found no bypass of S1–S5, and its fixes are all applied:
  - `grantFileProtocolExtraPrivileges` is kept on, because the renderer's module scripts load over `file://`.
  - The handshake cache has a generation guard.
  - The log sanitises `\r`, U+2028 and U+2029 and caps each message.
  - In the CLI, invalid state read from the store is now `EnvError`, so doctor reports it instead of aborting. A bad `pin` typed on the command line stays `UsageError` (exit 2).
  - `useAction` catches synchronous throws.
- **Round 2:** backend was ready to commit. Its one low item is fixed: `store install` now uses the strict version check. Frontend's fixes are applied too:
  - rejection handling in `NotificationBell` and for `takePendingProject`;
  - focus moves to the error-boundary fallback;
  - the Projects boundary resets on tab change.
- **Verified:**
  - typecheck, lint, 460 app tests and `npm run build`;
  - shellcheck on `05-app.sh`;
  - the python suites for versions, doctor, bind, paths and the JSON contract;
  - a live Electron smoke run. The window loads, IPC reaches the CLI, and navigating to a foreign `file://` page is blocked (`ERR_BLOCKED_BY_CLIENT`).
- **Not verified:** a packaged `electron-builder` build with the fuses applied. Run `npm run dist:mac` and check it once before the next release.
