## When to Use Managed Workflow

- No custom native code required
- Full reliance on Expo SDK modules
- Prioritizing OTA updates (`expo-updates`)
- Team without native iOS/Android experience

## When to Use Bare Workflow (or React Native CLI)

- Custom native modules not available in Expo SDK
- Performance-critical native integrations (Bluetooth, background audio, VoIP)
- Migrating an existing bare React Native project
- Fine-grained control over `Podfile` and `build.gradle`

## Expo — Critical Rules

**Detection**: `app.json` with `"expo"` key, `eas.json`, or `expo-modules-core` dependency.

```json
// app.json minimum required fields
{
  "expo": {
    "name": "AppName",
    "slug": "app-name",
    "version": "1.0.0",
    "orientation": "portrait",
    "icon": "./assets/icon.png",
    "splash": { "image": "./assets/splash.png" },
    "ios": { "bundleIdentifier": "com.company.app", "supportsTablet": true },
    "android": { "package": "com.company.app", "adaptiveIcon": { } },
    "plugins": []
  }
}
```

- **Config Plugins** (`app.json → plugins`): use for any native modification instead of editing `android/` or `ios/` directly — they survive `expo prebuild`
- **Never hand-edit** `android/` or `ios/` in Managed Workflow — they are regenerated by `expo prebuild` and changes will be lost
- **OTA updates** (`expo-updates`): always set `runtimeVersion` policy; test updates on staging before pushing to production; never push a breaking native change via OTA
- **SDK upgrades**: follow the official Expo upgrade guide; run `npx expo install --fix` after bumping SDK version to align all Expo package versions; test on both platforms before releasing

## EAS Build

```bash
# Configure once
eas build:configure

# Build for specific platform and profile
eas build --platform ios --profile preview
eas build --platform android --profile production

# Build locally (requires Xcode / Android Studio)
eas build --local --platform ios
```

**Profiles** (always define at minimum):
- `development` — debug build with dev client; use for daily development
- `preview` — release build for internal testing (TestFlight / Firebase App Distribution)
- `production` — App Store / Play Store submission build

## EAS Submit

```bash
# Submit directly after build
eas submit --platform ios --latest
eas submit --platform android --latest
```

- Always set `appleId`, `ascAppId`, and `appleTeamId` in `eas.json` under `submit.production`
- For Android: store the upload keystore in EAS Credentials — never commit it to the repo
